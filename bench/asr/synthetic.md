# Синтетический набор звонков: ASR и судья с точным эталоном

**Всё здесь синтетика.** Диалоги написаны LLM (`h200-gemma`) по матрице сценариев, выговорены TTS и пропущены через модель телефонного канала. Текст сценария — точный эталон: CER/WER, привязка к спикеру и вердикты судьи считаются относительно него, а не относительно другого ASR (как в `summary.md` и `noise-floor.md`). Числа ниже измерены этим прогоном; абсолютные значения на реальных звонках они не предсказывают (см. «Ограничения»).

## Метод

- Диалоги: 40 (EN 8, KZ 8, RU 24), звук 46–74 с (среднее 60 с, всего 40.0 мин). Оператор + клиент, у части диалогов первой идёт реплика IVR-бота. Для каждого диалога задан профиль качества (чистый / без приветствия / без идентификации / грубость / оскорбление / без завершения / неверная консультация / комбинация) и замысел по критериям c01–c08 (`bench/asr/synthetic/scripts.json`).
- TTS: `alemai/k2-fsa/OmniVoice` через aigw, один вызов на реплику, голос только `default` (поле `instructions` отвергается HTTP 400). TTS рисует новый голос на каждый запрос (сырой F0 одной роли внутри диалога гулял в пределах ~120–250 Гц), управлять голосом нельзя, поэтому каждая реплика приводится к целевому F0 своей роли (rubberband, `formant=preserved`; оператор 115 Гц, клиент 215 Гц + темп 1.04, бот 165 Гц + темп 0.95; F0 меряется по сырой реплике). Паузы 250–700 мс (seed), точные границы реплик сохранены.
- Телефонный тракт: моно → полосовой фильтр 300–3400 Гц → 8 кГц → G.711 μ-law (кодирование и декодирование) → белый шум с SNR 15–25 дБ (seed по id) → MP3 16 кГц моно, 48 кбит/с (как реальные записи).
- ASR: все включённые провайдеры из `config/asr.toml`, которые настроены, на деградированном MP3; подсказка языка как в сервере (только KZ → `kk`, остальные авто). Локальные (H200) — по одному запросу; `h200-gigaam-v3` и `h200-t-one` — только RU (русскоязычные движки); `h200-whisperx-kk` не запускался отдельно: `h200-whisperx` получает `kk` для KZ так же, как на сервере. Ablation: 8 диалогов дополнительно в чистом 16 кГц MP3 без тракта.
- Метрики: CER/WER — нормализация `bench.asr.normalize` (регистр, ё→е, пунктуация); «среднее» — среднее по диалогам, «пул» — сумма правок / сумма длины эталона. Привязка к спикеру: доля слов эталона, время которых (слова равномерно по символам внутри реплики) попадает в сегмент с правильным спикером при лучшем сопоставлении меток и ролей; слово вне сегментов — ошибка. Петли — серии ≥5 одинаковых слов подряд в выводе. Задержка — время запроса к провайдеру.
- Судья: `h200-gemma`, per_criterion, k=1, чек-лист звонков. (а) точный сценарий как Record с истинными ролями; (б) вывод `asr_to_record` каждого провайдера. Флип — вердикт критерия отличается от вердикта на точном сценарии; MAE — |итог ASR − итог точного|. Строка `exact-rerun` — повторная оценка того же точного сценария (шум модели).

## Итог и сравнение с реальными звонками

Что реально получено: 40 диалогов (RU 24, KZ 8, EN 8), 46–74 с звука каждый; 9 провайдеров на деградированном звуке (`h200-gigaam-v3` и `h200-t-one` — только RU, 24 диалога), ablation на 8 диалогах; судья на точных сценариях (дважды) и на выводе каждого провайдера. Не запущено: `alem-gigaam` (выключен в конфиге), `openrouter-audio` (выключен), `h200-whisperx-kk` отдельно (см. метод). Пропуски: `or-gemini-transcribe` вернул пустой результат на 2 запусках (один — KZ degraded `syn-kz-001`); часть записей судьёй не оценена — см. колонку «не оценено» (отказ самого `asr_to_record`: «модель сократила текст при маскировании» ниже порога 70 % — у `kuspeech` 23 из 40, у `h200-whisperx` 11 из 40; у `aigw-whisper` 1 отказ судьи по невалидному ответу модели). У `kuspeech` сегменты строятся по паузам ≥0,8 с, а в синтетике паузы 0,25–0,7 с, поэтому весь звонок превращается в один сегмент: это артефакт синтетики, на реальных звонках с длинными паузами так не будет. Флипы и MAE у провайдеров с большим числом «не оценено» считаются только по оценённым диалогам и несопоставимы с полными строками.

Топ по пулу CER на RU (деградированный звук): KuSpeech 0.030, FreedomSpeech 0.058, Gemini 0.065, aigw-whisper 0.075, GigaAM-v3 0.078, WhisperX 0.085, alem-whisper 0.091, alem-turbo 0.104, T-one 0.145. По флипам вердиктов судьи (все языки, только оценённые): alem-turbo 0.078, aigw-whisper 0.083, FreedomSpeech/alem-whisper/WhisperX 0.103, GigaAM 0.115, Gemini 0.132, T-one 0.203; шум самого судьи (exact-rerun) 0.006. По привязке к спикеру на RU лучший GigaAM-v3 (0.866), дальше Gemini 0.822, FreedomSpeech 0.696, T-one 0.621, WhisperX 0.606 (при двух ролях случайная привязка даёт около 0.5). Петель распознавания (≥5 одинаковых слов подряд) не было ни у одного провайдера. Судья на точных сценариях попал в замысел в 223 ячейках из 270.

### Ограничения

- TTS чище и регулярнее реальной речи; одно семейство голосов (OmniVoice), голос выбирается случайно на каждый запрос и не управляется, различие ролей — искусственная нормализация тона (оператор ≈116 Гц, клиент ≈217 Гц). Диаризация проверена только на этой разведённой паре; реальные голоса могут разделяться хуже или лучше.
- Привязка к спикеру считает времена слов равномерно внутри реплики (слов-таймингов у большинства провайдеров нет), так что это оценка с погрешностью в пределах реплики.
- Белый шум и μ-law — упрощённая модель телефонии; реальные каналы дают потери пакетов, эхо, музыку ожидания.
- KZ: круговой тест через `h200-whisperx-kk` на чистом звуке дал долю слов с казахскими буквами 0.68 против 0.66 в сценарии, то есть по этому признаку речь распознаётся как казахская, а не русская, и казахскую часть не помечаем ненадёжной. Но это проверка косвенная (Whisper в режиме `kk` мог «дотянуть» акцент до казахской орфографии), CER круговой 0.20 в среднем с выбросами (`syn-kz-008` 0.68, `syn-kz-005` 0.31), и n = 8; выводы по KZ предварительные.
- Замысел профилей качества проверен только судьёй (223/270 ячеек); ручной вычитки сценариев не было. Слабые места: c02 (16/28), c03 (26/40) и грубость без оскорбления (`rude`, 12/20) — судья и сценарии здесь расходятся, различить без ручной проверки нельзя.
- Ablation: у `alem-whisper-turbo` чистый звук хуже телефонного (CER 0.195 против 0.134) на 8 диалогах — похоже на сбой отдельных запросов, а не на эффект тракта (причина не разбиралась).

### Воспроизведение

`python -m bench.synth_calls scripts|tts|checks|asr|judge|report`; сценарии и кэши детерминированы (seed 20261108), звук и сырой вывод ASR лежат в `data/asr/synthetic/` (в git не попадают). Время шагов: сценарии ≈1 мин (+0.7 мин перегенерация трёх), TTS ≈3.5 мин (повторно ≈3.5 мин после нормализации тона), проверки (F0 + KZ) ≈3 мин, ASR облачные ≈5 мин, локальные H200 ≈19 мин, судья ≈5.4 + 1.5 мин.
