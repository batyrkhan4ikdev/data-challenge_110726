# CQA: контроль качества диалогов

**fantastik 4** · Freedom Broker CQA Hackathon · Data Challenge 2026

Оцениваем каждый чат и звонок оператора по чек-листу, как QA-специалист: с обоснованием, ссылкой на реплику и итоговым баллом. Делаем это за секунды и на собственной модели.

---

## Задача

- QA проверяет вручную лишь малую долю диалогов; правила сложные: N/A, SLA 3 минуты, грубые ошибки отдельно от балла.
- Нужно: 8 критериев, веса, N/A с перераспределением, флаг грубой ошибки, апелляция и решение ревьюера, редактируемый и версионируемый чек-лист, RU/KZ/EN.
- Встраивание в Dynamics 365.

---

## Как работает

```
Датасет API → загрузчик → оценщик (gemma-4 31B, по вызову на критерий)
  → вердикт + обоснование + номера реплик + N/A-причина
  → скоринг (Decimal, half-up, перераспределение N/A) → карточка / results.json
  → апелляция → ревьюер → пересчёт итога (исходный и финальный сохраняются)
```

- Правила организаторов и пограничные случаи хранятся в `notes` чек-листа, а не в коде: жюри меняет правило и сразу переоценивает.
- Модель сама на нашем H200, данные клиентов не уходят в облако.

---

## Точность: как выбирали модель

| | Совпадение с разметкой, 60 DEV-чатов |
|---|---|
| **gemma-4 31B, по критерию (наш выбор)** | **0.93–0.94** |
| Qwen3.8-27B / Flash-Next | 0.91–0.92 |
| DeepSeek-V4.1 / Kimi-K2.6 | 0.90 / 0.85 |
| Gemini 4 Argon, Grok 4.7, DeepSeek-V4-Pro | на 1–3 п.п. ниже gemma на тех же чатах |
| ансамбль из 3 судей | ничья с gemma |

- Около 15 моделей и режимов. Голосование k=3 замерили — не помогает. Файнтюн не делали: на 65 диалогах его нельзя честно проверить.
- Наша разметка совпадает с ручной разметкой пяти других команд на **95–99%**.
- Реалистичная оценка на новых чатах **≈ 0.93 ± 0.02**. Это совпадение с метками, а не с экспертами организаторов.

## Надёжно и дёшево

- **Воспроизводимость:** 99.6% вердиктов совпадают между прогонами (температура 0).
- **Стоимость:** ≈ $0.003 за диалог на своём H200; весь DEV (65 диалогов) — $0.18.
- **Отказоустойчивость:** если модель недоступна, диалог автоматически уходит на запасную цепочку (Sonnet → Luna → glimmer); битая запись становится ошибкой в файле, а не падением прогона.
- **Контроль одной командой:** `run_batch.py <GROUP> --submit prod` пишет и проверяет `results/prod/results.json`.

---

## Продукт

- **Грубые ошибки** вынесены отдельно, с объяснением и цитатой: перевод денег оператору лично, платные «частные консультации», грубость, раскрытие данных до идентификации.
- **Карточка:** кольцо балла, «Почему снижена оценка» → «Перейти к фрагменту», «Оспорить оценку».
- **Апелляции:** очередь ревьюера, решение пересчитывает итог.
- **Чек-листы:** добавить, изменить или перевзвесить критерий → новая версия → «Переоценить по текущему чек-листу».
- **Аналитика** по группе и **«Факты диалога»**: первая реакция против SLA 3 мин, ожидание клиента, маскированные данные. Факты считаются без LLM.
- Встраивание в **Dynamics 365**: интерфейс без фреймворков, монтируется через `mountCqa(root, {apiBase})`.

## Звонки: свои транскрипты

Транскрипты звонков у организаторов слабые: «идентификацию успешно проеданная». Поэтому в карточке звонка можно выбрать источник транскрипта:

- **FreedomSpeech**, по умолчанию;
- наши модели;
- **«Вставить свой»**.

«Распознать заново» вживую: аудио → распознавание → роли оператор/клиент → маскирование персональных данных на нашей gemma.

| Бенчмарк, 5 DEV-звонков | CER к FreedomSpeech |
|---|---|
| GigaAM-v3 + pyannote (наш H200) | 12.6% |
| T-one + pyannote (наш H200) | 13.9% |
| Gemini 3.5 Transcribe | 14.2% |
| Whisper large-v3 | 17.7–29.7% |

Ручную оценку качества транскриптов делает участник команды, CER — согласие с FreedomSpeech, а не точность. Контроль — только чаты, ASR на него не влияет.

## Демо

1. Грубые ошибки: фильтр → p1-ru-022, p1-en-013.
2. Один диалог целиком: p1-ru-029 (балл, N/A, фрагменты); звонок p4-ru-003 с перемоткой аудио.
3. Апелляция → ревьюер → пересчёт итога.
4. Чек-лист: новый критерий и новый вес → переоценка.
5. Аналитика.
6. Свой транскрипт звонка.

Сценарий: `docs/demo.md`. Можем прогнать любые транскрипты при жюри: оценка чата занимает около 6 с.
