# CQA: контроль качества диалогов

**fantastik 4** · Freedom Broker CQA Hackathon · Data Challenge 2026

- Оцениваем **каждый** чат и звонок оператора по версионируемому чек-листу: вердикт, обоснование, номер реплики, N/A, флаг грубой ошибки.
- ≈ 6 с на диалог, ≈ $0.003 на **своём** H200: данные клиентов не уходят в облако.
- Апелляция → решение ревьюера → пересчёт итога. Правила QA меняет сам, без разработчика.
- Встраивается в Dynamics 365 (`mountCqa(root, {apiBase})`).

**Дальше — живой продукт:** чек-лист → диалоги → оценка → результат → апелляция → переоценка.

## Почему этому можно доверять

| | |
|---|---|
| Совпадение с разметкой, 60 DEV-чатов | **≈ 0.93** (RU 0.92 · KZ 0.96 · EN 0.96) |
| Наша разметка vs ручная разметка 5 других команд | **95–99%** |
| Сравнено моделей и режимов | ≈ 15, включая Gemini 4, Grok 4.7, DeepSeek-V4 и казахские LLM: никто не лучше gemma-4 31B |
| Воспроизводимость между прогонами | **99.6%** вердиктов |
| Контрольный прогон | одна команда → `results/prod/results.json`, без ручных правок |

Модель недоступна → автоматически запасная цепочка. Битая запись → строка `error` в файле, а не падение прогона.

## Звонки: зачем свой транскрипт

Транскрипт звонков организаторов для QA непригоден: «идентификацию успешно проеданная». Неверный текст даёт неверную оценку и неверное решение по оператору.

- По умолчанию **FreedomSpeech**, собственное STT Freedom; рядом 8 моделей с бейджем качества и «Вставить свой».
- «Распознать заново»: аудио → текст → роли → маскирование ПДн **на нашей модели**, ≈ 40 с.

| 5 DEV-звонков | CER к FreedomSpeech |
|---|---|
| GigaAM-v3 + pyannote (наш H200) | 12.6% |
| T-one + pyannote (наш H200) | 13.9% |
| Gemini 3.5 Transcribe | 14.2% |
| Whisper large-v3 | 17.7–29.7% |
