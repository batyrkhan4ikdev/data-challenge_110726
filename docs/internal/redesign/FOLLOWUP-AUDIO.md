Дополнение к редизайну, не забудь его: у звонков будет загрузка аудио и распознавание с выбором из двух провайдеров ASR. Вариант 1: **FreedomSpeech**. Вариант 2: **наша модель**, она ещё не выбрана. Сейчас в `server/` и `web/src/` этого нет: интерфейс звонка только проигрывает `audio_url` (`web/src/ui/transcript.ts:49-77`), а маршрутов ASR нет. Из фичи в редизайн входит только интерфейс. Сервер делает агент Арына, контракты меняет интегратор.

## Прочитай
- `docs/internal/research/freedomspeech.md`, особенно «Мини-план экстра-фичи», пункты 1–4 и 6. Там проверенный endpoint, ограничения (браузерный `User-Agent`, ссылка на mp3 живёт 1 час, маскирование ПДн) и целевой API: `POST /api/conversations/{cid}/transcribe?provider=…`, у `Evaluation` поле `transcript_source`, транскрипт звонка хранится в двух вариантах.
- `data/calls/freedomspeech.dev.json`: готовые транскрипты FreedomSpeech для 5 DEV-звонков в формате API организаторов.

## Что заложить в редизайн карточки звонка (`#/evaluation/p4-ru-003-3c6c365a`)
1. **Источник аудио.** Сценарии два: запись звонка по `audio_url` и загрузка своего файла (кнопка или зона drop, mp3/wav). Отрисуй состояния: нет файла, выбран, загружается с прогрессом, ошибка формата или размера, готово. Плеер остаётся native `<audio>`, переход к фрагменту по-прежнему перематывает запись (`audio.currentTime = offset_s`).
2. **Выбор провайдера ASR.** Сегментированный контрол или radio из двух пунктов: «FreedomSpeech» и «Наша модель». Список и подписи берутся с сервера, по образцу `GET /api/profiles`. Вторую модель не хардкодь: пока она не выбрана, пункт виден, но неактивен, с подписью «модель ещё не выбрана». Когда её подключат, UI не меняется. Рядом кнопка «Распознать» с состояниями: идёт (FreedomSpeech отвечает 7–13 с), готово, ошибка провайдера (403 от Cloudflare, лимит ключа) с понятным текстом и повтором.
3. **Переключатель транскрипта.** «API организаторов» / «FreedomSpeech» / «Наша модель». Показывай только варианты, которые есть у звонка. Номера реплик, evidence и перемотка работают в каждом варианте. В карточке видно, на каком варианте посчитана оценка (`transcript_source`). «Переоценить» запускает оценку на выбранном варианте.
   **Защита от чужих доказательств.** `web/src/ui/transcript.ts:64-77` ищет evidence и `offset_s` по `turn.idx` в том транскрипте, который открыт сейчас. У другого варианта ASR или у заменённого аудио свои реплики и тайм-коды, поэтому старые индексы укажут не на те реплики, а перемотка уйдёт не туда. Правило такое: доказательства, «Перейти к фрагменту» и подсветку expected показывай только когда открытый вариант транскрипта и аудио совпадают с теми, на которых посчитана оценка (`transcript_source` плюс идентификатор аудио). При другом варианте есть два пути: открыть оценку этого варианта, если она есть, или выключить ссылки на доказательства с подписью «Оценка посчитана по другому транскрипту — переоцените». Индексы между вариантами не переносить.
4. **Тексты** в `web/src/i18n.ts`, все стили под `.cqa`, токены редизайна, контраст ≥ 4.5:1, клавиатура и фокус. На 390px блок помещается без горизонтального скролла.

## Границы
- Маршрутов и полей, которых ещё нет в `server/` и `web/src/types.gen.ts`, не выдумывай. Если к твоему шагу API ASR ещё не готов, сверстай блок и все его состояния, но не показывай пользователю нерабочие кнопки: рендери блок, только когда сервер отдаёт список провайдеров. Отметь это в PR и в issue, чтобы агент Арына подключил API.
- Если API уже появился (проверь `server/routes/` и `types.gen.ts`), подключай по нему и прогони сценарий на копии store: распознать → переключить транскрипт → переоценить.
- Ключ `FREEDOMSPEECH_API_KEY` живёт только в `.env`. Никаких ключей в коде, скриншотах и логах. Ненужные сырые ответы ASR не сохраняй: в них ПДн.
- Демо-сценарии из `docs/demo.md` не должны сломаться.
